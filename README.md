# 🎛️ SampleHelp

Q&A-платформа для саунд-дизайнеров и синтезаторщиков. Загрузи аудио-пример звука — сообщество подскажет, как воссоздать его в Serum, Phase Plant, Vital и др.

**Стек:** чистый HTML5 + CSS3 + ванильный JavaScript (ES Modules, `.mjs`). Без фреймворков и сборщиков. Бэкенд (перезаход 48, Supabase полностью заменён — санкции): **свой стек** `backend/` — Node.js + Express + PostgreSQL + Socket.IO, хранение файлов на SSD, аутентификация JWT + bcrypt. Фронт общается с ним через адаптер `public/js/api.mjs` (флаг `USE_LOCAL_BACKEND` в `config.mjs`); при выключенном флаге работает **демо-режим** (слой `supabase.mjs`, данные в localStorage браузера).

## 🚀 Быстрый старт

```bash
npm install
npm start          # → http://localhost:3000 (демо-режим: данные в браузере)
npm run dev        # с автоперезапуском (nodemon)
```

**Со своим backend (полный стек):**

```bash
# 1) PostgreSQL 15+ и зависимости backend
cd backend && npm install
# 2) БД и схема (идемпотентно; Windows/PowerShell — см. backend/README.md)
export DATABASE_URL=postgres://postgres:MyPassword@127.0.0.1:5432/sh_dev
node src/migrate.js
# 3) сервер API + статика/SPA фронт на :3100
STATIC_DIR=../public node src/app.js     # → http://localhost:3100
# 4) перевести фронт на backend: в public/js/config.mjs
#    USE_LOCAL_BACKEND: true   (API_URL уже задан: http://localhost:3100)
```

Админ-владелец: `update owner_config set owner_email = 'вы@почта';` — первая
регистрация под этой почтой получает `is_admin` (бейдж 🛡, экран /moderation).
Живой смоук всей цепочки через адаптер: `cd backend && node tools/phase_c_smoke.mjs`.

> **Демо-режим (`USE_LOCAL_BACKEND: false`):** приложение работает
> с моковыми данными и **процедурно генерируемым аудио** (басы, пэды, FX
> синтезируются в WAV прямо в браузере). Вейвформы строятся по **реальным пикам**
> сгенерированных семплов — форма волны всегда соответствует звуку.
> Демо-изменения (аватар, настройки, контент) переживают перезагрузку страницы
> (LocalStorage); при обновлении кода со сменой версии демо-сидов выполняется
> **мягкий пересид**: ваш контент (вопросы, ответы, комментарии, сообщения,
> лайки, избранное, подписки, донаты, уведомления) и настройки профиля
> переносятся поверх новых сидов, ссылки на исчезнувший демо-контент чистятся,
> о пересиде показывается уведомление.

## 🔌 Свой backend вместо Supabase (перезаход 48)

Решение заказчика 2026-10-14: Supabase убирается ПОЛНОСТЬЮ (санкции/оплата),
вместо него — мини-ПК Ubuntu: Node.js + Express + PostgreSQL + Socket.IO +
Nginx, выход через Cloudflare Tunnel, файлы на локальном SSD. Фазы:
**A** (ядро backend) ✅, **B** (Socket.IO + серверный cron жизненного цикла) ✅,
**C** (фронт-адаптер `api.mjs`) ✅, **D** (деплой мини-ПК) — по команде.
Спека — `PLAN_BACKEND_REWRITE.md`, запуск и контракты — `backend/README.md`.

Переключение фронта: `USE_LOCAL_BACKEND: true` + `API_URL` в
`public/js/config.mjs`. OAuth удалён (вход только e-mail+пароль+сброс письмом);
регистрация без подтверждения почты; JWT: access 12h в localStorage + refresh
30d с ротацией (адаптер тихо обновляет пару на 401). Папка `supabase/`
(schema.sql/setup*.sql) — АРХИВ прежней облачной схемы; живая схема БД —
`backend/src/schema.sql`.

## 📸 Снимок проекта (filelist_with_content.txt)

Один файл со всем деревом проекта и содержимым текстовых файлов (~1,2 МБ) — удобный способ переносить проект между машинами и держать архивную копию. Генерация занимает **доли секунды**:

```bash
npm run filelist                # → ../filelist_with_content.txt (рядом с папкой проекта)
npm run filelist -- путь/дамп.txt   # свой путь назначения

# Восстановить проект из снимка:
node scripts/restore-filelist.cjs ../filelist_with_content.txt ../samplehelp_restored
```

Детали: `node_modules` и `.git` исключаются; бинарные файлы (картинки/аудио) перечисляются, но их содержимое не сохраняется; текстовые `.svg` сохраняются целиком. Формат совместим с исходным дампом (BOM, CRLF, маркеры `[📁 ПАПКА]`/`[📄 ФАЙЛ]`). Round-trip (дамп → восстановление → побайтовое сравнение) покрыт тестом `tmp_tests/test_filelist_roundtrip.mjs`. **Запускайте `npm run filelist` после завершённой работы — снимок всегда будет со свежим кодом.**

## ✨ Ключевые особенности

- **Лента**: клик по карточке раскрывает **ответы и комментарии прямо под карточкой**; клик по аватару/имени открывает профиль; заголовок ведёт на страницу вопроса.
- **Вопрос**: только заголовок, описание, синтезатор (если известен) и аудио — тип звука, сложность и теги **определяет отвечающий** в форме ответа.
- **Синтезатор «Другой»**: кнопка «+» добавляет свой вариант в **общий справочник** (`synth_catalog`) — он становится доступен всем.
- **Аудио**: вейвформа строго по реальным пикам семпла, обрезка регионами (WaveSurfer.js + офлайн-фолбэк), нормализация громкости через OfflineAudioContext; загрузка — в **Opus** (webm/opus 48 kbps mono через MediaRecorder в реальном времени с прогрессом, Safari — mp4/AAC, фолбэк без MediaRecorder — WAV): ~×30 к размеру против WAV. Пики вейвформ извлекаются ДО сжатия. **Маркеры («вот этот момент»)** — пины на мини-вейвформе + кликабельные чипы под ней — показываются во всех списках карточек: лента, «Избранное», вкладки профиля «Вопросы»/«Избранное» и витрина «Лучшие ответы» (клик по чипу играет с отметки и не открывает карточку). Спектрограмма и зацикливание не реализуются.
- **Профиль**: смена аватара (загрузка файла), ссылки добавляются кнопкой «+» — **платформа распознаётся автоматически** по URL и отображается с inline-SVG логотипом (Instagram, YouTube, SoundCloud, Spotify, Bandcamp, X, Telegram, TikTok…); DAW выбираются в модалке из справочника (`daw_catalog`), свой вариант — через «+». Шапка — обложка-вейвформа, аватар, статистика полосой и две полосы внизу: `🎛️ DAW` и `🧰 Арсенал`. Блок «Навыки» из продукта убран (2026-10-11); контакты и способы приёма вынесены из шапки — см. ниже.
- **Настройки профиля**: модалка «⚙ Настройки профиля» с **автосохранением** — кнопки «Сохранить» нет: текстовые поля (имя, био) сохраняются с debounce, переключатели и пикеры (обложка, коллаборации, DAW, арсенал, ссылки, контакты, способы приёма) — мгновенно; незавершённые изменения досохраняются при закрытии. Содержимое разбито на **пять секций** (Профиль / Ссылки и оснащение / Приватность / Контакты / Поддержка) с заголовками и разделителями; **липкий подвал** со статусом («Сохранение…» → «Сохранено ✓») и «Готово» виден на любой глубине скролла; в секции «Профиль» — смена фото тем же кроппером и превью обложки, в «Ссылках» — чипы уже установленных ссылок. Редакторы контактов и способов приёма перестроены по варианту «Г» (выбор заказчика по превью): способы — два **фикс-слота** 📱 СБП и 💳 Карта без селекта и кнопок (заполнил значение = способ включён, пусто = пунктирный слот «не указан»), контакты — **карточки с фиксированным видом** (иконка + название + 🗑), вид выбирается в эмодзи-меню при добавлении (занятые виды отключены, лимит 6). Переключателя языка здесь больше нет — интерфейс заморожен на ru (см. «i18n» ниже). Пустое имя не сохраняется; во время ввода поле не подменяется — откат к сохранённому имени только при потере фокуса.
- **Обложка профиля**: вейвформа детерминированно генерируется из `userId` (inline-SVG, у каждого своя волна) и рисуется одним из **пяти стилей на выбор пользователя** — Глубина, Зеркало, Спектр, Волна, Студия (`js/covers.mjs`, сохраняется в `profiles.cover_style`). Выбор — в «Настройках профиля»: превью каждого стиля живое, обложка меняется на глазах, выбранный стиль **сразу автосохраняется**.
- **Форматирование текста**: в вопросах, ответах и комментариях — `**жирный**`, `*курсив*`, `` `код` ``, блоки кода ```…```, `> цитаты`, `- списки`, автоссылки. Над полями ввода — мини-тулбар. Разметка своя (`js/format.mjs`): текст сначала полностью экранируется, поэтому вставить произвольный HTML/XSS нельзя. В превью ленты и профиля маркеры снимаются.
- **Контакты по бейджу «🤝 Открыт к коллаборациям» (2026-10-11)**: контакты (Telegram, e-mail, телефон, Discord, сайт, VK, своё; не больше 6) **не стоят в профиле списком** — их открывает бейдж-кнопка «🤝 Открыт к коллаборациям» рядом с именем: модалка «Как связаться» с чипами (иконка, значение, подпись, «Показать», «⧉ Скопировать», «↗ Открыть») и кнопкой «💬 Написать» во внутренний чат; владельцу — всё без маски и «⚙️ Изменить». **Приватность:** другим участникам контакты видны только при включённых **обоих** тумблерах профиля — `open_to_collab` (бейдж = точка входа) и `contact_consent` (явное согласие, по умолчанию выключено; в онбординге проставляется вместе с контактом, там же галочка «показывать бейдж»), e-mail и телефон до нажатия «Показать» маскируются (`a•••@nullsea.ru`, `+7 9•• •••-••-44`), анонимам по клику предлагается войти. Чипы не рендерятся в DOM страницы профиля — только в открытой модалке. **Оплата:** ряда с реквизитами в шапке тоже нет — кнопка ☕ «Поддержать автора» открывает одноимённую модалку со способами приёма (строго два: СБП по номеру телефона и банковская карта) и бесплатным «спасибо». ⚠️ Фильтрация по видимости пока **клиентская** (RLS отдаёт строку профиля целиком): серверный RPC `reveal_contact()` + вью без колонки `contact` запланированы на Этап 3 вместе с Terms/Privacy (152-ФЗ).
- **Жалобы и модерация**: «⚑ Пожаловаться» на вопрос/ответ/комментарий (не на своё) и **на профиль** — модалка с причиной (спам / оскорбления / чужой контент / **мошенничество и чужие реквизиты** / другое) и пояснением; повторная жалоба того же пользователя на тот же объект отклоняется, на свой профиль пожаловаться нельзя. Админы (`profiles.is_admin`) видят в меню аватара «🛡 Модерацию» (`/moderation`): вкладки «Новые/Все», содержимое цели цитатой (для профиля — био, контакты и реквизиты), «Отклонить», «Удалить контент» (с подтверждением) или «✓ Разобрано» для жалоб на профиль (профиль не удаляется). В демо админ — DemoUser.
- **Присутствие «кто онлайн» вместо общего чата**: общий чат отклонён до триггера ≥1,5–2k DAU; вместо него в ленте и в сайдбаре вопроса — чип со **стеком аватарок** и выпадающим списком «Сейчас онлайн» (имена-ссылки, пометка «(вы)», гости отдельным счётчиком — анонимы не показываются персонально). Приватность: opt-out «не показывать онлайн» удалён (2026-10-13) — в списке все залогиненные. Демо — симуляция пула имён с суточной кривой, реал — Socket.IO presence на backend (комната presence:global, username/аватар в track). Выключается флагом `FEATURES.PRESENCE`.
- **Подписка на теги — кликабельные #теги (2026-10-13, заход B)**: `#теги` в карточках ответов и тег синтезатора в карточках ленты — чипы-кнопки: клик подписывает на тег (анониму предлагается войти), повторный клик отписывает; подписанный чип — «✓ #тег» в меди, все чипы одного тега на экране синхронизируются, сайдбар-блок «Подписки» в профиле перерисовывается на месте. Клик по тегу **не** раскрывает карточку и не запускает плеер (capture + stopPropagation); в режиме справки клик показывает поповер вместо действия. Новый вопрос с этим тегом (синтезатором) порождает уведомление 🏷️ `new_question_tag` подписчикам (автору самому — нет). Состояние «подписан» — из кэша `store.subscriptions`, один `fetchSubscriptions()` на экран.
- **Без браузерных подсказок в полях (2026-10-13)**: автоподсказки/автозаполнение и нативные валидационные «пузыри» отключены на всех `form`/`input`/`textarea` — `autocomplete="off"` + `novalidate` (в модалке входа убраны прежние `autocomplete="username"/"email"/"current-password"`). Механика централизованная (`utils.mjs`: `disableBrowserHints` + MutationObserver и focus-слушатели в `initNoBrowserHints()`): новые поля получают защиту сами, регрессию держит статический скан исходников в `test_no_browser_hints.mjs`. Против браузеров, игнорирующих `off` (Chrome/Yandex ключуют сохранённые подсказки по name/id, менеджер паролей — по паре логина), добавлены случайный `name` на сессию у текстовых полей и readonly до фокуса на десктопе: снимается через 250 мс после фокуса (в момент клика поле ещё readonly — меню не раскрывается), клавиша снимает сразу с вставкой символа через execCommand, focusout возвращает; на тач-устройствах трюк выключен ради клавиатуры). Валидация — своя (тосты/инлайн-ошибки), spellcheck/autocorrect оставлены полезными для RU-текста.
- **Поддержка авторов и проекта (модель A)**: платформа **не проводит платежи, не проверяет получателя и не выступает гарантом** — получатель сам настраивает способы приёма в «Настройках профиля» (секция «💳 Поддержать автора»). С 2026-10-13 (`DEMO_DB_VERSION = 12`) способов **два канала: QR-код СБП** (автор загружает картинку из приложения банка) **и Boosty** (ссылка на страницу автора; платёж проводит сама платформа); в модалке «Поддержать автора» донор выбирает канал переключателем, если включены оба. QR-код (СБП-номер и карта удалены; старые виды отфильтровываются при чтении — `normalizeDonateMethods` в `public/js/donate.mjs`). Картинка даунскейлится до ≤600px/~380 КБ, декодируется локально (jsQR из `public/vendor/jsQR.js`, без сети) и проходит фишинг-разбор ДО сохранения и ДО любых переходов: тип содержимого, домен с подсветкой, опасные схемы, HTTP, homograph, punycode, IP, подозрительные TLD, сокращатели, typosquatting по брендам банков, поддомены-обманки; «Открыть ссылку» блокируется при danger-находках, для QR НСПК — памятка «проверьте получателя в приложении банка». Автоопределение вида по значению (телефон → СБП, 16–19 цифр → карта) и валидация перед сохранением (СБП ≥ 10 цифр, карта 16–19 цифр) — кривая строка остаётся в редакторе с подсказкой, но не записывается. Модалка «Поддержать автора · {имя}» показывает реквизиты кнопкой «Скопировать», у СБП — инструкция «перевод по номеру телефона → банк получателя» и бесплатное «спасибо» с сообщением (растёт счётчик «☕ N» на профиле, автору приходит уведомление). **QR-коды СБП отложены на следующий заход**: рабочий QR для приёма перевода физлицу нельзя сгенерировать на клиенте (payload `qr.nspk.ru` выдаёт НСПК с контрольной суммой, а персональный QR получатель создаёт в приложении своего банка), поэтому автор будет загружать готовую картинку QR + название банка; поля `qr_data_url`/`bank` зарезервированы в том же jsonb, SQL-миграция не потребуется. Способы проекта — в `CONFIG.DONATIONS_PROJECT`. Точки входа: чип «☕ Поблагодарить» на чужих ответах, ☕ на профиле, «Поддержать проект» в подвале. **Контекст переводов (2026-10-13):** донор видит готовое сообщение к переводу «SampleHelp · поддержка @автор» с кнопкой копирования (вставьте его в поле «сообщение» банка — автор поймёт, от кого приход) и блок «Я перевёл»: отметка суммы → автору уведомление «отметил(а) перевод N ₽ — сверьте с поступлением в банке»; автор подтверждает кнопкой «Получено ✓» прямо из уведомления или из списка «Отметки о переводах» в своей модалке → донору прилетает благодарность, статус записи «done». Антимошенническая памятка: перевод с сообщением «SampleHelp…» — донат с платформы; просьбы «вернуть ошибочный перевод» — мошенники. Платежи внутри платформы (ЮKassa, модель B) — в дорожной карте, когда появится юрлицо.
- **Правка и удаление своего**: вопрос (✏️/🗑 в ленте и на странице вопроса, правка — на `/ask?edit=<id>`), ответ (инлайн-форма внутри карточки), комментарий (инлайн). После изменения появляется метка «(изменено)». Удаление ответа-решения возвращает вопросу статус «открыт», счётчики обновляются на месте.
- **🗄 «Данные» (/admin, заход 50; русификация — заход 52)**: админ-просмотрщик таблиц backend-БД в стиле мини-pgAdmin, **строго чтение**: слева список таблиц с оценкой строк, справа грид — типы колонок, 🔑 у PK, сортировка кликом (на сервере), пагинация 50/100, значения по типам (jsonb свёрнут, время «N ч назад», uuid обрезан), клик по строке — карточка со всеми колонками. Названия таблиц и колонок — **по-русски** (словарь `admin_db.schema.*` в ru.json, 20 таблиц/136 колонок), оригиналы БД — в title-подсказках и мелких подстрочниках; неизвестное имя показывается оригиналом (fallback — новые таблицы не ломают экран); значения ячеек не переводятся. Синхронность словаря и `backend/src/schema.sql` проверяет `test_admin_db.mjs`. Секреты не показываются вовсе: `refresh_tokens`/`reset_tokens` скрыты, `users.password_hash` исключён из выдачи сервером. Вход: пункт «🗄 Данные» в меню аватара (только is_admin); в демо — заглушка (БД нет). SQL от клиента не принимается никогда. Превью: admin-ru-preview.html.
- **Контекстная справка «What's this?»**: иконка «?» в шапке за колокольчиком включает режим справки — функционал сайта временно блокируется (клики перехватываются в capture-фазе, интерфейс выглядит живым), а клик по любому элементу показывает, что он делает: спотлайт + поповер с описанием. Каталог — **95 пунктов** (`data-help` + i18n `help.items.*` в ru), клик по элементу без описания объясняет ближайшего предка. Дополнительно: **тур первого визита** (8 шагов со спотлайтом, «далее/пропустить», флаг в LocalStorage) и страница **/help** (FAQ из 8 разделов + запуск режима/тура); входы — «?» в шапке, «📖 Справка» в меню аватара и ссылка в подвале. Целостность каталога следит `tmp_tests/check_help_catalog.cjs`. **Палитра режима — никелевое серебро** (`--nickel-*`): спотлайт, бордеры поповера/баннера и активная «?» холодные серебряные, а не медные — смена тона сразу показывает, что включён особый режим (правило дизайн-системы: медь = бренд и действия, никель = подсказки). Кнопки внутри help-UI остаются общесайтовыми медными; страница /help — обычная контентная, без никеля.

## 💰 Монетизация (заложена, выключена)

Модули `marketplace.mjs`, `premium.mjs`, `affiliate.mjs` и таблицы `products`, `orders`, `subscriptions_premium`, `affiliate_links` — заготовки. Активация: `ENABLE_MONETIZATION: true` в `config.mjs`. Платёжная система не интегрируется — экраны показывают заглушку «Скоро».

**Реклама (Яндекс РСЯ)** — третий независимый рычаг (`ads.mjs`, `ENABLE_ADS: false` в `config.mjs`). Слоты: **лента** (после каждой 6-й карточки, `every` настраивается) и **сайдбар страницы вопроса** (под «Действиями»). Тёмная тема блоков (`darkTheme`), подпись «Реклама», статистика по срезам `statId`, скрытие пустых слотов (нет инвентаря для EN/DE-трафика или адблокер), корректный `destroy()` при уходе с экрана (SPA). Осознанно без полноэкранных форматов и без рекламы у плееров/рекордера/триммера.
Порядок включения: сайт на своём домене (Этапы 1+4 SCALE_PLAN) → регистрация и модерация в [Яндекс.Рекламе](https://ads.yandex.ru) (жёсткого порога по трафику нет) → создать RTB-блоки (тёмная тема) → вписать ID (`R-A-XXXXXX-N`) в `CONFIG.ADS.blocks` → `ENABLE_ADS: true`. До тех пор при включённом флаге видны пунктирные плейсхолдеры (реальный код Яндекса не грузится); при выключенном — в DOM ничего нет. Маркировка сетевых объявлений (erid/ЕРИР) — автоматически на стороне Яндекса.

**Аналитика (Яндекс.Метрика)** — `metrika.mjs`, `ENABLE_METRIKA: false` + `CONFIG.METRIKA` (counterId, webvisor выкл по умолчанию, clickmap/trackLinks/accurateTrackBounce). В демо и на localhost счётчик не грузится; SPA-переходы отслеживаются хитами `ym(..., 'hit', url)` по подписке на роут. Включение: номер счётчика из metrika.yandex.ru → `counterId` → флаг.

**SEO**: OG/twitter-теги и canonical в `index.html`, бренд-картинка `assets/og-cover.png` (1200×630), `robots.txt` (служебные разделы закрыты, Sitemap указан), `sitemap.xml`.
