# Настройка Supabase для SampleHelp — с нуля до работающего сайта

Всё время: ~10 минут. Все действия — в браузере и в папке проекта.

---

## Часть 1. Аккаунт и проект (3 мин)

1. Откройте **https://supabase.com** → **Start your project**
2. Войдите через GitHub (быстрее всего) или зарегистрируйтесь по email
3. Нажмите **New project** и заполните:
   - **Organization**: `Default` (создайте, если нет)
   - **Name**: `samplehelp`
   - **Database Password**: нажмите *Generate a password* и **сохраните его** (в блокнот/менеджер паролей — понадобится для подключения Access/DBeaver и админских задач)
   - **Region**: ближайший к вам (например, *Central EU (Frankfurt)*)
4. **Create project** → подождите 1–2 минуты, пока проект инициализируется

> 💡 Если у вас уже есть старый проект SampleHelp — новую создавать не нужно:
> просто откройте её и переходите к Части 2 (скрипт сам «досоздаст» недостающее).

---

## Часть 2. База данных — ОДНО действие (2 мин)

1. В левом меню дашборда: **SQL Editor** (иконка терминала `</>`)
2. Нажмите **New query**
3. Откройте в проекте файл **`supabase/setup.sql`** (рядом с этой инструкцией),
   выделите всё содержимое (`Ctrl+A`) и скопируйте (`Ctrl+C`)
4. Вставьте в редактор (`Ctrl+V`) → нажмите **Run** (или `Ctrl+Enter`)
5. Ожидаемый результат:
   - надпись **«Success. No rows returned»**
   - внизу — два списка-отчёта: ~20 **таблиц** (profiles, questions, answers…)
     и **4 бакета** (avatars, marketplace-files, presets, question-audio)

Скрипт идемпотентен: если что-то уже было создано раньше — он не сломается,
а просто досоздаст недостающее. Можно запускать повторно в любой момент.

> 🔁 **Уже запускали setup.sql раньше?** Запустите его ЕЩЁ РАЗ (тем же способом).
> Новые версии добавляют недостающие колонки и правила без поломки существующих
> данных. Например, обновление «Форматирование + правка/удаление» добавляет:
> колонки `edited_at` (вопросы/ответы/комментарии), политики удаления ответа
> и правки/удаления комментария, триггер `answers_delete_cleanup`
> (удаление ответа-решения возвращает вопросу статус «открыт»).
>
> ⏳ Обновление **«Жизненный цикл решённого вопроса»** добавляет: колонки
> `solved_at` / `purge_at` / `purged` / `purge_summary` / `reminder_24h` /
> `reminder_3d` (вопросы), `awarded_rep` (ответы), `solutions_count` /
> `purged_answers_count` (профили), функции `mark_solution()` (отметка решения:
> таймер удаления +25 реп. помощнику) и `run_question_lifecycle()` (удаление
> просроченных решённых вопросов в заглушку + напоминания авторам).
> Без повторного запуска скрипта приложение в реальном режиме продолжит
> работать, но новый жизненный цикл не включится.
>
> 📍 Обновление **«Маркеры момента»** добавляет: колонку `markers` (ответы —
> «вот этот момент» в аудио ответа, до 2 штук). Отметки момента в комментариях
> убраны из продукта — скрипт заодно удаляет колонку `marker_time` у `comments`,
> если она успела создаться. Без повторного запуска скрипта отправка ответов
> с маркерами в реальном режиме не сохранится.
>
> 🎨 Обновление **«Обложка профиля»** добавляет: колонку `profiles.cover_style`
> (стиль вейвформы-обложки: `depth` / `mirror` / `spectrum` / `wave` / `studio`,
> по умолчанию `depth`) и CHECK-ограничение `profiles_cover_style_check`.
> Пользователь выбирает стиль в модалке «Редактировать профиль». Без повторного
> запуска скрипта сохранение обложки в реальном режиме упадёт с ошибкой
> `column "cover_style" does not exist`.

## Часть 3. Авторизация для тестов (1 мин)

1. В левом меню: **Authentication** → **Sign In / Providers** (или «Providers»)
2. Откройте **Email**
3. Выключите переключатель **Confirm email** → **Save**

> Зачем: без этого после регистрации Supabase ждёт подтверждения по письму.
> Для локальной разработки удобнее, чтобы вход работал сразу.
> Перед публичным запуском продукта — включите обратно.

OAuth (Google/GitHub/Apple) настраивать НЕ обязательно — приложение само
спрашивает у Supabase, какие провайдеры включены, и показывает только их.

---

## Часть 4. Ключи в приложение (1 мин)

1. **Project Settings** (шестерёнка внизу слева) → **API Keys**
2. Скопируйте два значения:
   - **Project URL** — вида `https://xxxxxxxx.supabase.co`
   - **publishable key** (`sb_publishable_...`) или **anon** (`eyJ...`) —
     подойдут оба
3. Откройте в проекте файл **`public/js/config.mjs`** и впишите их:

```js
SUPABASE_URL: 'https://xxxxxxxx.supabase.co',
SUPABASE_ANON_KEY: 'sb_publishable_...',
```

(или просто пришлите эти два значения — я впишу их сам;
publishable-ключ не является секретом, данные защищает RLS)

> ⚠️ **Никогда** не вписывайте во фронтенд `secret` / `service_role` ключ —
> он обходит все политики безопасности.

## Часть 5. Запуск и проверка (3 мин)

```bash
cd samplehelp
npm install      # только первый раз
npm start
```

1. Откройте **http://localhost:3000** и обновите с очисткой кэша: `Ctrl+Shift+R`
2. В подвале страницы должно быть: **`SUPABASE: подключено ✓`**
3. Нажмите «Регистрация» → создайте аккаунт → пройдёт онбординг (био, DAW, навыки)
4. Создайте вопрос: загрузите любой аудиофайл → обрежьте лишнее → опубликуйте
5. Проверьте в дашборде Supabase:
   - **Table Editor → profiles**: ваша строка
   - **Table Editor → questions**: вопрос со ссылкой на аудио
   - **Storage → question-audio**: папка с вашим user-id и файл внутри
6. Смените аватар в профиле → файл появится в **Storage → avatars**,
   после `F5` аватар останется на месте

### Тест мультипользовательности и Realtime
Откройте сайт во втором браузере (или в окне инкогнито), зарегистрируйте
второго аккаунта, напишите сообщение первому — оно придёт **мгновенно,
без перезагрузки страницы**.

## Устранение неполадок

| Симптом | Причина / решение |
|---|---|
| В подвале `SUPABASE: ошибка подключения` | Ключи не вписаны / опечатка в URL или ключе; смотрите текст тоста |
| `Cannot read properties of null` | Устаревший кэш браузера — обновите `Ctrl+Shift+R` (SDK теперь локальный, ошибка устранена) |
| `Bucket not found` при загрузке аудио | Не выполнен `setup.sql` (Часть 2) |
| После регистрации «пусто» / нет сессии | Не выключен **Confirm email** (Часть 3) |
| Кнопки Google/GitHub/Apple не видны | Так и задумано: провайдеры не включены в Authentication → Providers |
| `new row violates row-level security` при вставке | Вы вошли не под тем пользователем или сессия истекла — перелогиньтесь |
| Проект «спит» после недели простоя | Free-план приостанавливает неактивные проекты — откройте дашборд и нажмите Restore, первое подключение займёт ~минуту |
