Контекстная справка и тур (`test_help.mjs`):
- «?» за колокольчиком в шапке включает режим: функционал ВСЕХ элементов блокируется
  (перехват pointerdown/mousedown/click/keydown/wheel в capture-фазе document —
  без disabled, UI выглядит живым), клик по любому элементу показывает поповер
  с описанием (help.items.* ×3 локали), спотлайт подсвечивает элемент и затемняет остальное;
- фолбэк: клик по вложенному элементу → ближайший предок с data-help; без него — тост;
- выход: Esc, кнопка баннера, повторный клик по «?»; клики внутри help-UI (крестик
  поповера, кнопки тура) работают; при включении режима закрываются «бесхозные»
  панель уведомлений и меню аватара;
- клавиатура: Enter/Space по фокусу показывают справку, прочие клавиши глушатся
  (Tab/Ctrl/Meta/Alt не трогаем); wheel на канвасах блокируется; тач-скролл НЕ
  блокируется (preventDefault у pointerdown — только для мыши);
- тур первого визита: 8 шагов (лента → «задатель» → карточка → мини-плеер → «кто
  онлайн» → колокольчик → меню аватара/вход → сама «?»), шаги без элементов
  пропускаются, «пропустить/понятно» пишут флаг samplehelp_tour_seen в LocalStorage;
  maybeAutoTour стартует через 1,2 с только без флага;
- /help: 8 секций FAQ + CTA «Режим» (navigate на главную + старт) и «Тур»;
- check_help_catalog.cjs: data-help из index.html и всех .mjs (включая dataset.help
  и ключи TOUR_STEPS) ↔ help.items во всех трёх локалях, в обе стороны без пропусков и сирот.

Триммер: зум + маркеры (`test_trimmer_zoom.mjs`):

  (через паузу превью на currentTime=3.5);
- пин маркера при любом зуме (1×/2×/4×/8×, кнопки и Ctrl+колесо) стоит на
  математически верном x = (time − viewStart) / viewDur × width;
- Ctrl+колесо прямо по маркеру — пин остаётся под курсором (якорь зума);
- высокий бар вейвформы (всплеск) на всех зумах рисуется ПОД пином (±полоса
  не «размазывается»): пики берутся из декодированного буфера (4000 точек),
  бар i покрывает пики [floor(tt0·N/D) .. ceil(tt1·N/D)−1] без заезда на соседей;
- панорама колесом: пин и всплеск едут вместе; getResult возвращает маркер
  относительно обрезанного фрагмента.

Триммер: драг маркеров + ▶ от маркера (`test_marker_drag.mjs`):
- пин маркера перетаскивается по волне (захват ±9px, пин в приоритете над

  курсор над пином — ew-resize;
- клик по пину БЕЗ движения ничего не запускает: прослушивание — только ▶ в чипе;
- маркер никогда не выходит за регион: кламп при драге, при движении границ
  (слайдеры/драг/сброс) маркер «едет» с краем, getResult больше не «теряет»
  маркеры молча;
- ▶ в чипе: старт ровно от маркера (currentTime = marker − start региона),
  повторный клик — пауза, третий — продолжить без пересоздания аудио;
  чип подсвечен (.playing), кнопка ▶/⏸, играющий пин крупнее на волне;

- удаление играющего маркера останавливает превью.

Сообщения vs уведомления (`test_msg_badge.mjs`):
- личные сообщения больше НЕ попадают в колокольчик: уведомления типа 'message'
  фильтруются в fetchNotifications (и в демо, и в реальной БД — старые строки тоже скрыты),
  демо-сид n3 и запись message-уведомления в subscribeMessages удалены;
- вместо них — счётчик непрочитанных (#msg-count) на иконке «Сообщения»:
  начальное значение из fetchConversations(), +1 на входящее (onIncomingMessage),
  свои сообщения не считаются, при открытом диалоге с отправителем не растёт
  (сообщение сразу читается), после markThreadRead — refreshUnreadMessages();
- выход из аккаунта сбрасывает unreadMessages (store + auth.doLogout);
- панель уведомлений (#notif-panel) вынесена в body и раскрывается position: fixed
  ровно под колокольчиком (positionPanel(): центр иконки, клампинг к краям экрана,
  перепозиционирование при resize);
- событие messages:new по-прежнему диспатчится для будущих подписчиков.

  чата/ответов не затронуты (там idle-кнопка — задуманный вход);
- пока аудио нормализуется и пока оно на экране, «📁 Выбрать файл» и
  «⏺ Захват с компьютера» заблокированы (title-подсказка), видна «✕ Очистить аудио»
  (подтверждение через модалку); очистка убирает триммер/маркеры/рекордер,
  чистит аудио в черновике и возвращает кнопки в работу;
- cleanup экрана теперь сохраняет состояние триммера в черновик и разбирает
  триммер (раньше AudioContext/превью могли утекать на следующий экран).

Правка вопроса с аудио (`test_ask_draft.mjs`, секции 9–13):

  маркеры можно двигать/переименовывать, регион — резать, как при создании;
- сохранение дифференцированное (форма — источник правды, лишнего не перезагружаем):
  тронуты ТОЛЬКО маркеры → в patch уходит один `markers` (audio_url и пики не меняются),
  обрезан регион → новый файл + waveform_data + маркеры, ничего не тронуто → аудио-поля

- регион «весь клип» определяется как start≈0 и end≈min(duration, TRIM_MAX_SECONDS)

- перерисовка в режиме правки (i18n:changed): исходное аудио и поля переживают её

- в демо-БД audio_url регенерируется из audio_kind при чтении, поэтому удаление
  файла наблюдаемо по markers=[] (в реальном режиме payload.audio_url=null удаляет файл).
