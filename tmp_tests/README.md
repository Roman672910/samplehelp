Что покрыто:
- отметка решения: +25 реп. помощнику (один раз), solved_at/purge_at = +7 дней, уведомление;
- смена решения без отмены — таймер не сбрасывается; отмена — таймер снят, репутация сохранена навсегда;
- удаление по таймеру: содержимое/ответы/комментарии/лайки чистятся, остаётся purge_summary,
  счётчики отвечающих (purged_answers_count) сохраняются, автору — финальное уведомление;
- напоминания: 24 ч и 3 дня после первого ЧУЖОГО ответа, самоответы не считаются;
- заглушка не попадает в ленту, видна в профиле/избранном/чате;
- UI: баннер с отсчётом, закрытая форма ответа, неактивные «Ответить»/«В избранное»,
  клик «✓ Решение» → ре-рендер через роутер, «Отменить решение» через модалку;
- новый ответ на решённый вопрос отклоняется слоем данных (в БД — триггер answers_no_new_on_solved).

Плеер вопроса (`test_marker_player.mjs`):
- клик по чипу маркера — игра с этого момента, повторный клик по играющему — пауза;
- клик по маркеру после паузы — снова старт С МАРКЕРА (а не с места паузы);
- клик по другому маркеру во время игры — переход на него без остановки;
- кнопка ▶ работает как раньше (с текущего места) и снимает привязку к маркеру,
  перемотка по вейвформе и конец трека — тоже;
- играющий маркер подсвечивается медным (.marker-chip.playing), подсказка в title (ru/en/de).

A/B-плеер (`test_ab_player.mjs`):
- референс вопроса и ответ почти всегда разной длины — переключение A↔B
  синхронизирует треки ПО ПРОЦЕНТУ длины (50% одного = 50% другого),
  поэтому оба доигрывают до конца вместе и короткий трек не «упирается» в конец;
- после ended оба трека отматываются в начало, ▶ стартует заново;
- страховка: если трек стоит на конце без события ended, ▶ тоже перематывает в начало;
- клик по вейвформе и клавиши A/B/Space ведут себя согласованно.

Триммер: зум + маркеры (`test_trimmer_zoom.mjs`):
- аудио-стаб 10с с ОДНИМ всплеском ровно на 3.5с; маркер ставится туда же
  (через паузу превью на currentTime=3.5);
- пин маркера при любом зуме (1×/2×/4×/8×, кнопки и Ctrl+колесо) стоит на
  математически верном x = (time − viewStart) / viewDur × width;
- Ctrl+колесо прямо по маркеру — пин остаётся под курсором (якорь зума);
- высокий бар вейвформы (всплеск) на всех зумах рисуется ПОД пином (±полоса
  не «размазывается»): пики берутся из декодированного буфера (4000 точек),
  бар i покрывает пики [floor(tt0·N/D) .. ceil(tt1·N/D)−1] без заезда на соседей;
- панорама колесом: пин и всплеск едут вместе; getResult возвращает маркер
  относительно обрезанного фрагмента.

Триммер: драг маркеров + ▶ от маркера (`test_marker_drag.mjs`):
- пин маркера перетаскивается по волне (захват ±9px, пин в приоритете над
  ручками региона), время в чипе обновляется живьём, у пина — тултип «5.0s»,
  курсор над пином — ew-resize;
- клик по пину БЕЗ движения ничего не запускает: прослушивание — только ▶ в чипе;
- маркер никогда не выходит за регион: кламп при драге, при движении границ
  (слайдеры/драг/сброс) маркер «едет» с краем, getResult больше не «теряет»
  маркеры молча;
- ▶ в чипе: старт ровно от маркера (currentTime = marker − start региона),
  повторный клик — пауза, третий — продолжить без пересоздания аудио;
  чип подсвечен (.playing), кнопка ▶/⏸, играющий пин крупнее на волне;
- ended, «Прослушать» (игра с начала региона) и удаление маркера гасят подсветку;
- удаление играющего маркера останавливает превью.

Сообщения vs уведомления (`test_msg_badge.mjs`):
- личные сообщения больше НЕ попадают в колокольчик: уведомления типа 'message'
  фильтруются в fetchNotifications (и в демо, и в реальной БД — старые строки тоже скрыты),
  демо-сид n3 и запись message-уведомления в subscribeMessages удалены;
- вместо них — счётчик непрочитанных (#msg-count) на иконке «Сообщения»:
  начальное значение из fetchConversations(), +1 на входящее (onIncomingMessage),
  свои сообщения не считаются, при открытом диалоге с отправителем не растёт
  (сообщение сразу читается), после markThreadRead — refreshUnreadMessages();
- выход из аккаунта сбрасывает unreadMessages (store + auth.doLogout);
- панель уведомлений (#notif-panel) вынесена в body и раскрывается position: fixed
  ровно под колокольчиком (positionPanel(): центр иконки, клампинг к краям экрана,
  перепозиционирование при resize);
- событие messages:new по-прежнему диспатчится для будущих подписчиков.

Типизированные ссылки в ответах (`test_answer_links.mjs`):
- формат данных answers.links: [{ url, kind, label? }], kind ∈ ''|video|article|docs|preset|other;
  старый формат (голые строки) конвертируется normalizeLinks() на лету — миграция БД не нужна;
- автоопределение вида по домену: youtube/vimeo/twitch/tiktok/rutube → «Видео-туториал»,
  habr/medium/substack/dev.to → «Статья», ableton/image-line/xfer/kilohearts/docs.* → «Документация»,
  github/splice/gumroad/patreon/boosty → «Пресет / сэмпл», неизвестный домен → «Ссылка»;
- виджет формы (ответ + правка ответа): строки [иконка][URL][тип][✕], кнопка «＋ Добавить ссылку»,
  счётчик «N из 3», на трёх строках добавление блокируется и видна подсказка «Максимум 3 ссылки»;
- ручной выбор типа (touched) не перебивается автоопределением при дальнейшем вводе URL;
- «Другое…» открывает поле своей пометки (label, до 60 символов);
- валидация перед отправкой: только http(s) («Некорректная ссылка»), без дубликатов
  («Эта ссылка уже добавлена»), пустые строки игнорируются, ошибка подсвечивает строку;
- рендер в карточке ответа: «[иконка платформы] Видео-туториал · youtube.com»
  (target=_blank, rel=noopener noreferrer), фирменные SVG-иконки из profile.mjs.

Форма /ask: черновик + одноразовый захват + блокировка (`test_ask_draft.mjs`):
- смена языка (роутер перерисовывает экран по i18n:changed) больше НЕ сбрасывает
  форму: черновик (модуль question.mjs) хранит текст, «Другой» синтезатор + своё
  название, категорию, нормализованное аудио и состояние трима; после перерисовки
  всё восстанавливается, триммер пересоздаётся с регионом и маркерами 1-в-1
  (новая опция initialState у createTrimmer + лёгкий getState() для сохранения);
- черновик живёт до публикации или «Отмены» (переживает уход с экрана и возврат);
  в режиме правки (?edit=<id>) привязан к id вопроса;
- захват с компьютера — одноразовый (singleShot у createRecorder): после записи,
  отмены ✕ и даже отмены выбора источника UI рекордера убирается целиком —
  вторая кнопка «⏺ Захват с компьютера» не появляется; микрофонные рекордеры
  чата/ответов не затронуты (там idle-кнопка — задуманный вход);
- пока аудио нормализуется и пока оно на экране, «📁 Выбрать файл» и
  «⏺ Захват с компьютера» заблокированы (title-подсказка), видна «✕ Очистить аудио»
  (подтверждение через модалку); очистка убирает триммер/маркеры/рекордер,
  чистит аудио в черновике и возвращает кнопки в работу;
- cleanup экрана теперь сохраняет состояние триммера в черновик и разбирает
  триммер (раньше AudioContext/превью могли утекать на следующий экран).

Правка вопроса с аудио (`test_ask_draft.mjs`, секции 9–13):
- «✏️ Редактировать» → /ask?edit=<id> больше НЕ показывает пустую форму: исходный
  клип вопроса подтягивается (fetch audio_url) прямо В ТРИММЕР — вейвформа, оба
  маркера с заметками из БД, кнопки источника заблокированы, «✕ Очистить аудио» видна;
  маркеры можно двигать/переименовывать, регион — резать, как при создании;
- сохранение дифференцированное (форма — источник правды, лишнего не перезагружаем):
  тронуты ТОЛЬКО маркеры → в patch уходит один `markers` (audio_url и пики не меняются),
  обрезан регион → новый файл + waveform_data + маркеры, ничего не тронуто → аудио-поля
  вообще не попадают в patch, «Очистить» + save → вопрос без аудио (audio_url=null, markers=[]);
- регион «весь клип» определяется как start≈0 и end≈min(duration, TRIM_MAX_SECONDS)
  (помогает trimmer.getState(), он теперь отдаёт и duration);
- замена исходного аудио новым (файл/захват) → полная перезагрузка файла, как раньше;
- смена языка в режиме правки: исходное аудио и поля переживают перерисовку
  (draft.audioBlob + trim-состояние), гонка загрузки отсекается счётчиком audioLoadSeq;
- в демо-БД audio_url регенерируется из audio_kind при чтении, поэтому удаление
  файла наблюдаемо по markers=[] (в реальном режиме payload.audio_url=null удаляет файл).

Обложка профиля (`test_profile_cover.mjs`):
- генераторы вынесены в `public/js/covers.mjs`: пять стилей — depth, mirror,
  spectrum, wave, studio; каждый детерминирован из userId (один пользователь —
  всегда одна волна), чистый inline-SVG без зависимостей;
- стиль хранится в `profiles.cover_style` (колонка добавлена в setup.sql и
  setup_part1.sql; CHECK-ограничение — отдельным идемпотентным блоком, потому что
  «add column if not exists» не навешивает constraint на уже существующую колонку);
  NULL/неизвестное значение → DEFAULT_COVER_STYLE ('depth');
- выбор — в модалке «Настройки профиля»: пикер с ЖИВЫМИ превью всех стилей
  (role=radio, aria-checked), клик мгновенно перерисовывает обложку под модалкой
  и СРАЗУ автосохраняет cover_style (кнопки «Сохранить» больше нет);
- закрытие модалки (✕ / Escape / клик по фону / «Готово») ловит MutationObserver
  на #modal-root, который проверяет наличие в DOM именно своего контента
  (вложенные модалки DAW/арсенала/ссылок его не срабатывают): при закрытии
  незавершённые сохранения досохраняются (flush), а экран профиля
  перерисовывается — отката стиля больше нет, всё уже сохранено;
- id градиентов/фильтров уникальны на обложку (`shcov-<стиль>-<userId>`): пять
  превью в пикере и шапка профиля не перебивают друг друга (раньше id sh-cover-grad
  был один на всю страницу);
- `.profile-cover g { opacity: .5 }` убран — прозрачности слоёв заданы внутри SVG,
  общее правило глушило бы все планы; добавлены растворение краёв (::after) и
  появление обложки с учётом prefers-reduced-motion.

«Настройки профиля» с автосохранением (`test_settings_autosave.mjs`):
- переключатель языка УБРАН из шапки (в index.html нет .lang-switcher) и переехал
  в модалку «⚙ Настройки профиля»: те же классы .lang-switcher, активную кнопку
  поддерживает updateSwitcherUI(); клики ловит document-делегирование из
  initI18n() — поэтому работает и для динамически созданного переключателя;
- смена языка из модалки переводит её ЖЕ на глазах: статические подписи — через
  data-i18n (applyTranslations), динамические (пикер обложки, превью DAW/арсенала,
  чипсы навыков, заголовок, статус) — через слушатель i18n:changed; выбор пишется
  в localStorage (samplehelp_locale);
- автосохранение без кнопки «Сохранить»: текстовые поля (имя, био) — debounce
  700 мс, чипсы навыков — 400 мс, переключатель коллабораций и все пикеры
  (обложка/DAW/арсенал/ссылки) — мгновенно; сохранения идут через одну
  последовательную очередь (позднее не перезапишет раннее при гонке);
- статус-строка (#ed-autosave, role=status): подсказка «Изменения сохраняются
  автоматически» → «Сохранение…» → «Сохранено ✓» (2,5 с) → снова подсказка;
  при ошибке — тост и подсказка;
- пустое имя не сохраняется и НЕ подменяется во время ввода: debounce,
  сработавший при пустом поле в фокусе, просто не пишет пустое в БД
  (currentPatch подставляет lastSavedName); визуальный откат к сохранённому
  имени — только на blur или когда поле не в фокусе (иначе старое имя
  вставлялось под курсор посреди набора и текст «склеивался» — баг от 08.10);
- закрытие с незавершённым debounce (✕ сразу после ввода) не теряет изменения —
  flush при удалении модалки из DOM, затем экран профиля перерисовывается;
- «Готово» (#ed-done) и Enter в поле — дожидаются сохранений и закрывают модалку;
- регрессия бага закрытия при выделении текста: mousedown внутри модалки +
  mouseup на фоне (и обратный драг фон→модалка) окно НЕ закрывают — fix в
  openModal (utils.mjs): закрытие по фону требует, чтобы И нажатие, И отпускание
  мыши произошли строго на оверлее (раньше click после выделения прилетал на
  общего предка-оверлей и закрывал модалку). Чинит ВСЕ модалки проекта.
