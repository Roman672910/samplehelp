modblock=short_plus_link, notify=status_only) + требование заказчика «чтобы у
каждого не было такой функции» (§4). Журнал: WORKLOG «Сделано», запись 36.
Откат: `../filelist_baseline_2026-10-14_before_mod_guide.txt`.**

## 0. Контекст

Модерация живая с захода (4): таблица `reports` (unique «жалобщик+цель»), экран
`/moderation` (guard по `profiles.is_admin`), RLS-контур; заход (18) добавил
жалобу на профиль (причина `fraud`, решение «✓ Разобрано» без удалений).
Обсуждение 2026-10-14 выявило три пробела и одну дыру безопасности:

1. Участник не знает «правил игры»: что считать спамом/оскорблением/копирайтом/
   мошенничеством, что происходит с жалобой после отправки.
2. Модератор не видит регламент на рабочем месте: матрица «причина → решение»,
   нюанс дублей, граница «не удаляем за вкус».
3. Жалобщик не получает ответа: петля обратной связи не замкнута.
4. **Дыра (боевой режим):** политика `profiles_own_write` = `update using
   (auth.uid() = id)` БЕЗ ограничения колонок → любой authenticated прямым
   запросом к PostgREST может выставить себе `is_admin = true` (самоповышение).
   Клиентский `updateProfile` шлёт только поля UI, но клиент — не граница
   защиты. В демо дыры нет (данные локальные).

## 1. Публичная секция «Жалобы и модерация» в /help

Существующая секция `helpPage.sections.moderation` ПЕРЕПИСЫВАЕТСЯ и
расширяется (сейчас она из двух предложений и содержит чужеродную фразу про
7-дневный архив решённых вопросов — это тема lifecycle, её убираем):

- где кнопки ⚑ (чужой вопрос/ответ/комментарий/профиль) и что жалоба — только
  на чужое, анониму предлагается вход;
- причины с примерами: спам (реклама, офтоп-повторы), оскорбление, чужой
  контент/копирайт, мошенничество («верните ошибочный перевод», «подтвердите
  код», перевод на чужие реквизиты — перекрёстная ссылка на антимошенническую
  памятку модалки поддержки), другое;
- механика: одна жалоба на цель от человека (повторная — duplicate), комментарий
  до 500 знаков;
- что дальше: модератор видит карточку с содержимым цели; решения — отклонить /
  удалить контент / «разобрано» (профиль); **жалобщик получает уведомление о
  факте решения** (см. §3);
- честная граница: модерация не редактирует чужой контент и не читает ЛС;
  спор о вкусе — не нарушение.

Ключи: переписать `helpPage.sections.moderation` (1 лист, перезапись значения).

## 2. Чек-лист модератору на /moderation (только админу)

Короткая матрица в 4–5 строк над списком жалоб + ссылка «подробнее в справке»
(вариант заказчика short_plus_link; полный текст живёт в §1, экран не
превращается в простыню):

| Причина | Действие |
|---|---|
| спам, оскорбление | удалить контент (или отклонить, если на грани) |
| копирайт | до Этапа 3 — удалить чужой контент; полноценный DMCA там |
| мошенничество (профиль) | «✓ Разобрано»; ничего не удаляем; при рецидиве — вручную через SQL |
| другое | по содержанию; сомнение трактуем НЕ в пользу удаления |

Плюс строки-правила: «не удаляем за вкус»; «на одну цель может быть несколько
жалоб от разных людей — после разбора цели закройте остальные карточки
вручную» (группировка дублей — бэклог); «статусы: new → dismissed | actioned».

i18n: `moderation.guide_title` + `moderation.guide_rows` (4–5 листов-строк) +
`moderation.guide_more`. Ссылка — интерактивный элемент ⇒ `data-help="
moderation_guide"` + `help.items.moderation_guide` (каталог +1).
Блок рендерится только внутри guard'а экрана (не-админ туда не попадает).

## 3. Уведомление жалобщику о решении (status_only)

- В `setReportStatus(id, status)` после успешной записи: если status ∈
  {dismissed, actioned} → уведомление РЕПОРТЁРУ этой строки жалобы:
  type `report_status` (CHECK на тип нет — схема не меняется),
  payload `{ status, target_type }` — без цитат и причин (минимум ПДн).
- Рендер (notifications.mjs): иконка 🛡 в TYPE_ICONS; тексты-факты:
  `notifications.type_report_actioned` = «Ваша жалоба рассмотрена: контент
  удалён» / `notifications.type_report_dismissed` = «Ваша жалоба рассмотрена:
  нарушений не найдено, жалоба отклонена»; для target_type='profile' в
  actioned-варианте — «…приняты меры организационного характера» (профиль не
  удаляется — честность формулировки). Клик по уведомлению никуда не ведёт
  (цель могла быть удалена) — навигацию не добавляем.
- Несколько жалобщиков на одну цель: уведомляется только репортёр обработанной
  строки (закрыл дубли вручную — они получат свои уведомления).
- Демо: сид-уведомление не добавляем (экран не пустой благодаря сидам жалоб);
  покрытие — тестом.

## 4. Кто может быть модератором (модель и защита)

Роль одна: `profiles.is_admin` (булево, default false). Градаций
«модератор/владелец» сейчас нет (бэклог Этапа 3–4 при реальном потоке).

- **Демо:** админ — только сид u-demo (`is_admin: true` в сидах). UI-тумблера
  нет; в `DEMO_MIGRATE_PROFILE_FIELDS` флаг не входит (миграция не переносит и
  не «воскрешает»); остальные сиды и любые пользовательские профили — не админы.
- **Бой:** админом становится ТОТ, кому владелец проекта выставил флаг вручную
  в базе (SQL Editor Dashboard: update profiles set is_admin = true where
  id = '…'; снятие — тем же способом false). Никакого клиентского пути
  назначения нет и в этом заходе не появляется: до запуска модератор один
  (владелец), команда из 2+ человек — триггер бэклога (RPC
  `grant_moderator(target_id)` с проверкой is_admin вызывающего + аудит).
- **Критерии назначения (политика, текст в SETUP.md):** доверие и репутация
  (rating/solutions_count), отсутствие разобранных жалоб на самого кандидата;
  минимально достаточное число админов; снятие при неактивности.
- **Защита от самоповышения (фикс дыры из §0, идемпотентно в setup.sql /
  setup_part1.sql):** column-level grants —
  `revoke update on table public.profiles from authenticated;` затем
  `grant update (username, avatar_url, bio, links, cover_style, open_to_collab,
  donate_methods, contact, contact_consent) on table public.profiles to
  authenticated;`
  Прямой `update({is_admin:true})` отклоняется на уровне привилегий (42501),
  RLS-политики не меняются; триггеры счётчиков (rating и т.п.) выполняются от
  владельца таблицы и не страдают. Анon/update не имел и не имеет.
  Чек-лист живого прогона (Этап 1, SETUP.md): попытка самоповышения из консоли
  → ошибка 42501; штатное сохранение настроек → 200.
- **Границы полномочий модератора (для памяток):** читать все жалобы и менять
  их статусы; удалять ЛЮБОЙ вопрос/ответ/комментарий через контур жалоб
  (политики *_admin_delete); НЕ может: редактировать чужой контент, читать
  чужие ЛС, банить/удалять пользователей, назначать админов, видеть скрытые
  контакты сверх правил видимости (в карточке fraud-жалобы — только то, что
  цель сама указала как контакты/реквизиты).
- **Аудит «кто решил»:** колонки resolved_by у reports сейчас нет; до запуска
  (один админ) не нужна — бэклог вместе с командой модераторов.

## 6. Бэклог (не в этот заход)

- Группировка дублей жалоб по цели на /moderation (одна карточка = цель +
  список жалобщиков, решение применяется ко всем строкам цели).
- Команда модераторов: RPC grant/revoke с аудитом, колонка resolved_by,
  экран «команда» (Этап 3–4).
- «Мои жалобы» участника (считаем ненужным, пока петлю закрывает уведомление).
- DMCA-процесс копирайта (Этап 3).
